`00-INDEX.md`는 길잡이다. 각 본문은 다른 파일 없이도 이해되도록 작성했으므로, 급한 장애나 특정 기능 인계에서는 해당 프로젝트 또는 작업 문서부터 바로 읽어도 된다. 상태 표기의 뜻은 다음과 같다.

- **완료**: 구현과 필요한 반영이 끝났으며 일상 운영·확인만 남았다.
- **진행 중**: 일부 환경 미반영, 검증·배포 게이트 또는 후속 구현이 남았다.
- **검토만**: 설계·영향 분석이 중심이고 본 구현은 시작하지 않았거나 별도 범위다.
- **조사만**: 증거 수집과 원인·대안 정리까지 했으며 수정·운영 조치는 별도다.

## 6. 공통으로 알아둘 사실

1. 로컬 맥은 AWS 콘솔·CLI와 DB에 닿지 않는다. ECS·Lambda·SSM·실 DB 스키마·실행 프로세스는 회사 VDI에서만 확인할 수 있다.
2. 브랜치 반영, 배포, DB 적용은 서로 다른 상태다. `main`에 코드가 있어도 ECS 이미지·EC2 jar·Lambda zip·DDL은 **미배포** 또는 **미확인**일 수 있다.
3. ECS 배포 스크립트는 저장소의 태스크 정의 JSON을 자동 등록하지 않고 AWS의 최신 리비전을 재사용한다. 환경변수·시크릿을 바꿨다면 새 리비전을 먼저 등록한다.
4. 플랫폼 Spring 설정에서는 같은 키가 yml과 SSM에 함께 있으면 yml이 우선할 수 있다. SSM으로 옮겼다고 끝내지 말고 yml 리터럴을 제거하거나 실제 우선순위를 검증한다.
5. 리베이스·squash·cherry-pick 전 커밋 해시는 어느 기준 브랜치에도 없을 수 있다. 메시지나 해시 존재만 보지 말고 `git merge-base --is-ancestor`와 tree diff로 반영 내용을 확인한다.
6. `backend-api-main`은 여러 팀이 함께 쓰는 대형 저장소다. `stg` 371커밋을 통째로 운영 승격하지 말고 기능 트랙별 포함·제외 목록과 회귀 범위를 만든다.
7. Redis가 권위인 기능은 eviction·TTL·재부팅을 장애 조건으로 다룬다. DB 행이 있다고 현재 상태로 간주하지 않는다.
8. 외부 계약·출동 요청은 네트워크 실패와 업무 거절을 분리한다. 자동 재시도는 중복 계약·중복 출동을 만들 수 있다.
9. 시간은 저장·메시지·서버 계산에서 UTC를 기준으로 하고 표시 경계에서 KST로 바꾼다. 로그와 Athena partition은 각각 기준 시각을 확인한다.
10. 로그에는 토큰, 인증코드, 전화번호, 이름, CI, 키 원문을 남기지 않는다. 오류 추적에는 requestId·serial·correlationId와 단계 코드를 쓴다.
